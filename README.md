# vex: Windows x64 и ARM64

Проект собирается в два отдельных исполняемых файла: x64 и ARM64 (AArch64).
Для ARM используется нативная ARM64-сборка, с 64-битными указателями.

## Сборка

Нужны CMake 4.2 или новее, Visual Studio с компонентами **Desktop development
with C++**, MSVC для x64/ARM64 и Windows SDK с библиотеками обеих архитектур.
Предустановки используют стандартный генератор CMake для установленной Visual Studio.
Сборку можно выполнять на Windows x64 или Windows ARM64.

```powershell
cmake --preset windows-x64
cmake --build --preset x64-release

cmake --preset windows-arm64
cmake --build --preset arm64-release
```

Результаты:

| Платформа | Исполняемый файл |
| --- | --- |
| x64 | `out/build/windows-x64/Release/vex.exe` |
| ARM64 | `out/build/windows-arm64/Release/vex.exe` |

Для отладки доступны профили сборки `x64-debug` и `arm64-debug`; результаты
находятся в соответствующих каталогах `Debug`. В Visual Studio конфигурации
`windows-x64` и `windows-arm64` доступны через `CMakePresets.json`.

Если генератор по умолчанию переопределён в окружении, укажите установленную
Visual Studio явно, например:

```powershell
cmake --preset windows-arm64 -G "Visual Studio 18 2026"
```

MSVC runtime линкуется статически (`/MT`, `/MTd`); отладочные символы компилятора
встраиваются в объектные файлы (`/Z7`), а линкер создаёт PDB исполняемого файла.
32-битные ARM/x86 и ARM64EC
не поддерживаются. Рендеринг использует Windows API, DirectX 11 и Direct2D;
эта поддержка ARM64 относится к Windows.

## Работа с Java

Архитектура целевой JVM определяется по PE-заголовку загруженной `jvm.dll`.
Поэтому ARM64-сборка выбирает инструкции x64 для Java x64 под эмуляцией и
инструкции AArch64 для нативной Java ARM64. Смещения структур читаются из
экспортированных таблиц HotSpot целевого процесса.

Сжатие объектных ссылок (`UseCompressedOops`) и указателей классов
(`UseCompressedClassPointers`) обрабатывается независимо. Поддерживаются
обычные заголовки объектов HotSpot; при включённом `UseCompactObjectHeaders`
нужно запускать Java с `-XX:-UseCompactObjectHeaders`.
JVM другого типа, неподдерживаемая архитектура или отсутствующие необходимые
поля HotSpot приводят к отказу подключения с сообщением в консоли.

## Проверки

```powershell
ctest --preset x64-release
ctest --preset arm64-release
```

Тесты проверяют PE32+/архитектуры, границы и выравнивание переходов, чтение и
запись 64-битных значений, восстановление защиты страниц и исполнение
изменённого перехода с очисткой кеша инструкций. Также проверяется загрузка
маппингов из каталога проекта, включая пути с кириллицей. Запускайте ARM64-тесты на
Windows ARM64; x64-тесты работают также под эмуляцией на Windows ARM64.

Для проверки подключения к настоящей JVM используйте JDK 21 и тестовую
Java-программу (Minecraft не требуется):

```powershell
.\tests\verify-jvm.ps1 -JavaHome "C:\Path\To\JDK" `
    -TestExecutable ".\out\build\windows-arm64\Release\architecture_tests.exe"
```

Сценарий запускает отдельные процессы Java с четырьмя сочетаниями настроек
сжатия указателей. Проверяются таблицы HotSpot, поиск класса и полей,
объектные и примитивные массивы, запись статической ссылки и повторное
подключение. По завершении тестовые процессы останавливаются.

Проверено на Windows ARM64 с MSVC 19.51: сборки Debug/Release и CTest для
обеих архитектур, исполнение нативного ARM64-кода и x64-кода под эмуляцией.
Интеграционные проверки прошли с HotSpot 21 x64 (Temurin) и ARM64 (Microsoft
OpenJDK): оба клиента подключаются к обеим JVM во всех четырёх режимах сжатия
указателей. Полный игровой сеанс Minecraft не проверялся.
